1. Τι σαρώθηκε

Το τρέχον site τρέχει σε nopCommerce με το theme Uptown (server-rendered .NET MVC, jQuery, εικόνες από /images/thumbs/). Σαρώθηκαν όλοι οι τύποι σελίδας — όχι το σύνολο των προϊόντων, αλλά ένα αντιπροσωπευτικό δείγμα ανά τύπο.

ΕΜΠΟΡΙΚΕΣ ΣΕΛΙΔΕΣ

9 κατηγορίες 1ου επιπέδου → 3 επίπεδα βάθος → ~200 leaf κατηγορίες

ΤΟ ΣΥΜΠΕΡΑΣΜΑ ΣΕ ΜΙΑ ΠΑΡΑΓΡΑΦΟ
Το περιεχόμενο υπάρχει και είναι πλούσιο· η δομή παρουσίασής του είναι το πρόβλημα. Κάθε σελίδα φορτώνει ολόκληρο το mega-menu (~200 links) στο DOM, οι σελίδες προϊόντος επαναλαμβάνουν τον ίδιο πίνακα προδιαγραφών δύο φορές, τα meta descriptions κατηγοριών είναι κενά, τα φίλτρα δεν αποτυπώνονται σε URL, και ο εμπορικός λόγος («350 καταστήματα», δόσεις χωρίς κάρτα, δωρεάν φύλαξη) είναι θαμμένος σε στατικά banner. Η μετάβαση σε Next.js + custom CMS δεν είναι restyling: είναι αναδιάταξη του περιεχομένου σε components με σαφή data contracts, ώστε το marketing να χτίζει σελίδες χωρίς development.

2.1 Global shell — header, mega-menu, footer

ΣΗΜΕΡΑ ΠΡΟΤΑΣΗ ΣΕ ΕΠΙΠΕΔΟ COMPONENT

2.2 Αρχική

Σήμερα: ένα hero banner 1920×400, 14 promo tiles ως σκέτα PNG (όλο το κείμενο μέσα στην εικόνα — μηδέν SEO, μηδέν responsive control, μηδέν accessibility), ένα carousel «Προτάσεις Δροσιάς», τρία blog teasers και δύο ξεχωριστές φόρμες newsletter. Δεν υπάρχει καμία προσωποποίηση ούτε είσοδος στις κατηγορίες.

Πρόταση: η αρχική γίνεται 100% συνθέσιμη από widgets (§4). Σειρά αναφοράς: HeroSlider → CategoryQuickNav → DealCountdownRail → PromoMosaic (κείμενο ως HTML πάνω από art-directed εικόνα) → ProductRail ×2 (δυναμικά: εποχικό, best sellers) → BrandStrip → ServicesTeaser → StoreFinderTeaser → EditorialRail → NewsletterBand.

2.3 Κατηγορία & λίστα προϊόντων (PLP)

Φίλτρα χωρίς URL
Οι επιλογές facet δεν αποτυπώνονται σε shareable URL και το «Showing __ of __ results» εμφανίζεται κενό. Λύση: facets σε searchParams (?brand=lg,samsung&size=55&price=400-900), canonical στην καθαρή κατηγορία, noindex,follow σε συνδυασμούς >1 facet, indexable landing pages για ~40 εμπορικά ζεύγη (π.χ. «Τηλεοράσεις 55 ιντσών OLED»).
13 ομάδες φίλτρων, μηδέν ιεραρχία
Σε «Τηλεοράσεις» εμφανίζονται ισότιμα «Εύρος Οθόνης» και «USB Cloning» (μία μόνο τιμή: ΟΧΙ). Λύση: FacetGroup με ranking από το CMS (primary / secondary / collapsed), αυτόματη απόκρυψη facet με <2 τιμές ή 0 αποτελέσματα, counts ανά τιμή, «top 5 + Δες όλα».
Κάρτα προϊόντος χωρίς σήματα
Η διαθεσιμότητα («Άμεσα Διαθέσιμο» / «σε 2-4 εργάσιμες» / «κατόπιν παραγγελίας») είναι σκέτο κείμενο· η έκπτωση δεν υπολογίζεται· λείπει σύγκριση. ProductCard: badge έκπτωσης (%), StockPill με 3 καταστάσεις & χρώμα, δόση/μήνα, energy label, hover swap 2ης εικόνας, checkbox σύγκρισης, quick-add.
Pagination 20 σελίδες
200+ τηλεοράσεις σε σελίδες των 10. Λύση: 24/σελίδα, «Φόρτωσε περισσότερα» με πραγματικά paginated URLs κάτω από το κουμπί (SEO + accessibility), διατήρηση θέσης scroll στο back.
Κενό meta description
Σε όλες τις κατηγορίες. Λύση: πεδία SEO στο CMS ανά κατηγορία + fallback template με αριθμό προϊόντων, εύρος τιμών και brands.
Category hub = απλή λίστα
Οι σελίδες 1ου/2ου επιπέδου δεν καθοδηγούν. Λύση: ξεχωριστό template CategoryHub: SubcategoryTiles + «Αγόρασε ανά χρήση» (widget) + BuyingGuide (σύνδεση με blog) + ProductRail των top sellers.

4. Custom CMS με δυναμικά widgets

Το CMS δεν κρατά HTML. Κρατά δομημένο περιεχόμενο και μια λίστα widgets ανά ζώνη σελίδας. Το frontend αποφασίζει πώς αποδίδεται. Έτσι μια αλλαγή στο design system εφαρμόζεται σε όλες τις σελίδες ταυτόχρονα.

ΜΟΝΤΕΛΟ ΠΕΡΙΕΧΟΜΕΝΟΥ
Page (slug, template, seo, zones[])
Widget (type, props, visibility, schedule, audience)
Product · Category · Brand (από PIM/ERP, read-only στο CMS)
Store (γεωσυντεταγμένες, ώρες, υπηρεσίες)
Service · Article · FaqItem · LegalDoc
Redirect (from, to, status)
Navigation (δέντρο, ανεξάρτητο από το δέντρο κατηγοριών)
ΖΩΝΕΣ ΑΝΑ TEMPLATE
home: hero, main
categoryHub: aboveGrid, belowGrid, sidebarPromo
plp: banner, belowGrid
pdp: belowBuyBox, belowSpecs, crossSell
editorial / service / legal: main
global: announcementBar, trustStrip, footer
Κάθε ζώνη δηλώνει ποια widget types επιτρέπονται — δεν μπαίνει HeroSlider σε PDP.

Δυναμικά δεδομένα στα widgets

Το κρίσιμο σημείο: ένα widget δεν «κολλάει» προϊόντα με το χέρι. Δηλώνει query. Ο editor βλέπει ζωντανό preview των αποτελεσμάτων και μπορεί να καρφιτσώσει (pin) συγκεκριμένα προϊόντα στην κορυφή.

SOURCE ΠΩΣ ΤΡΟΦΟΔΟΤΕΙΤΑΙ CACHE
manualΛίστα SKU από τον editortag product:{sku}
category / tagΚατηγορία ή ετικέτα + sort + limitISR 10′
savedSearchΑποθηκευμένο facet query (π.χ. «TV, 55″, OLED, <1200€»)ISR 10′
bestsellersΠωλήσεις 30 ημερών από ERP, ανά κατηγορίαnightly job

Λειτουργίες που πρέπει να έχει ο editor

· Drag & drop widgets μέσα σε ζώνη, με ζωντανό preview στην πραγματική σελίδα
· Προγραμματισμός δημοσίευσης/απόσυρσης (κρίσιμο για κλιματιστικά, Black Friday, φοιτητικά)
· Visibility rules: συσκευή, νέος/επιστρέφων, γεωγραφία, UTM
· Draft → preview link → approval → publish, με audit log
· Ένα asset pipeline: upload μία φορά, αυτόματα AVIF/WebP σε 6 μεγέθη, υποχρεωτικό alt
· SEO panel ανά σελίδα (title, description, OG, canonical, robots) με προειδοποίηση αν λείπει
· A/B δύο εκδοχών του ίδιου widget
· Redirects UI για τη μετάπτωση (§6)

5. Αρχιτεκτονική Next.js

ROUTE RENDERING ΣΗΜΕΙΩΣΕΙΣ

Data layer. Ένα packages/commerce με typed clients (PIM/ERP, CMS, search, payments) και Zod schemas στα σύνορα. Καμία σελίδα δεν καλεί API απευθείας. Cache tags: product:{sku}, category:{id}, page:{slug}, nav — webhook από PIM/CMS καλεί revalidateTag.

Εικόνες. Το σημερινό /images/thumbs/*_480.jpeg αντικαθίσταται από next/image με AVIF/WebP, σωστά sizes, blur placeholder και priority μόνο στο LCP. Μηδέν κείμενο μέσα σε εικόνα.

SEO. Metadata API ανά route, JSON-LD (Product με AggregateOffer & availability, BreadcrumbList, LocalBusiness, FAQPage, Article), δυναμικά sitemaps ανά τύπο, hreflang έτοιμο για μελλοντικό EN.

6. Animation: GSAP ή Framer Motion

Δύο βιβλιοθήκες, καθαρός διαχωρισμός ευθυνών — αλλιώς διπλασιάζεται το bundle χωρίς λόγο.

FRAMER MOTION → UI STATE
Mega-menu panels, MiniCartSheet, modals & popovers (AnimatePresence), filter drawer, accordion, tabs, layout transitions σε grid/list toggle, micro-interactions σε buttons, badge pop στο καλάθι, page transitions.

Γιατί: declarative, δεσμευμένο στο React lifecycle, σωστό exit animation, μικρό για component-level δουλειά.
GSAP → SCROLL & TIMELINES
HeroSlider timelines, ScrollTrigger σε StepFlow & Timeline, pinned sections σε brand storytelling, count-up στο StatBand, horizontal rails με drag inertia, PromoMosaic parallax, reveal sequences.

Γιατί: ακρίβεια σε πολύπλοκες αλληλουχίες, ScrollTrigger. Φορτώνεται δυναμικά μόνο στα routes που το χρειάζονται.
ΚΑΝΟΝΕΣ ΠΟΥ ΔΕΝ ΠΑΡΑΒΙΑΖΟΝΤΑΙ
Μόνο transform και opacity · καμία animation δεν κρύβει τιμή, απόθεμα ή CTA · prefers-reduced-motion απενεργοποιεί τα πάντα πλην opacity · διάρκειες 150–400ms στο UI, ≤900ms στο storytelling · καμία animation στο LCP element · animation libraries πάντα σε client component πίσω από dynamic().
